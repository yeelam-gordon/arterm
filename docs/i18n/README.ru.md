При обрыве клиента или VPN сборки и агенты продолжают работу на удалённом Windows. Вернитесь в ту же оболочку.

*Схема работы с английскими подписями, не реальный снимок и не доказательство тестирования.*

- **Работа продолжается без клиента.** Сборки, агенты и долгие команды работают на удалённом Windows-хосте при закрытии клиента, потере VPN или перезагрузке ноутбука.
- **Вернитесь к работе, а не в пустую оболочку.** Подключитесь к тому же процессу интерактивной оболочки с его переменными и рабочим каталогом.
- **Просмотрите вывод за время отсутствия.** При подключении воспроизводится сохранённый вывод терминала; объём хранения ограничен, возможны пропуски, это не полный журнал.

## Требования и доверие

arTerm — нативная программа Windows на Rust. Нужны Windows с обеих сторон, один аккаунт GitHub для туннелей и разрешённые исходящие подключения. Хост должен работать, пользователь — оставаться в системе. Перезагрузка, выход пользователя, сбой, выключение или exit в удалённой оболочке завершают процесс без восстановления. Для обычных неинтерактивных задач может хватить одобренного канала удалённых команд.

Сборки x64/ARM64 подписаны сертификатом для разработки, которому Windows по умолчанию не доверяет; это не производственные выпуски. До установки, запуска или добавления сертификата в доверенные выполните проверки в PowerShell, не изменяющие систему:

1. Присвойте переменной `$archive` путь к скачанному ZIP. `Get-FileHash -LiteralPath $archive -Algorithm SHA256` выдаёт `.Hash`: сравните с одноимённым ZIP в публичной `SHA256SUMS` этого выпуска, не со списком из архива. Нет значения или оно отличается — остановитесь; совпадение не доказывает безопасность.
2. После совпадения хеша ZIP распакуйте архив и откройте PowerShell в каталоге с распакованными файлами. `Get-FileHash -LiteralPath .\arTerm-Dev.cer -Algorithm SHA256` вычисляет хеш сертификата; `$certificate = [System.Security.Cryptography.X509Certificates.X509Certificate2]::new((Resolve-Path -LiteralPath .\arTerm-Dev.cer).Path)` сохраняет объект сертификата, но не выводит поля; выполните `$certificate.Subject; $certificate.Thumbprint`, чтобы вывести имя и отпечаток. Сравните с [закреплёнными значениями/проверкой (английский)](../../DEVELOPMENT-INSTALL.md#certificate-identity), не только имя; на этом этапе не импортируйте сертификат в хранилище доверенных сертификатов.
3. По очереди присваивайте переменной `$file` пути к `arTerm-Client-Setup.exe`, `arTerm-Host-Setup.exe`, `arterm.exe`, `arterm-host.exe`. `Get-AuthenticodeSignature -LiteralPath $file` показывает `.Status` и `.SignerCertificate`. Все четыре должны быть `Valid`, отпечаток и байты сертификата должны совпасть с закреплённым CER. Завершите [проверку идентичности/подписей (английский)](../../DEVELOPMENT-INSTALL.md#inspect-extracted-executable-signatures-without-running-them) до запуска любой EXE.

Ручное доверие требует отдельного явного одобрения и разрешения политики; затем проверьте снова. Не-`Valid`, неизвестный подписант или несовпадение — остановка, не обход предупреждений/контролей. Хосту нужен разрешённый Windows Script Host/VBScript.

Сохранённый вывод, обычная история оболочки и файлы восстановления могут содержать команды, пути, код и секреты. Защищайте их на обеих машинах и удаляйте чувствительные сведения из журналов, снимков и материалов поддержки перед отправкой. Защита учётных данных DPAPI не означает шифрование всех файлов или отсутствие содержимого. Исключения содержимого в диагностике готовности имеют более узкий охват.

<a id="native-setup"></a>

## Настройка

[Технический справочник (английский)](../../QUICKSTART.md)

После успешных проверок и разрешения политики запустите arTerm-Host-Setup.exe на хосте и откройте новый PowerShell:

```powershell
arterm-host setup --name my-devbox
```

Завершите вход в туннель и сохраните команду регистрации, напечатанную хостом. Локально установите arTerm-Client-Setup.exe, откройте новый PowerShell с тем же аккаунтом GitHub и выполните именно эту команду с фактическим путём хоста. Клиент уже инициализирован, arterm setup не нужен. Подключитесь локально с новым именем сеанса:

```powershell
arterm connect my-devbox MyProof --shell powershell
```

<a id="native-proof"></a>

## Проверка той же оболочки

В подключённом удалённом PowerShell выполните и запишите PID и каталог:

```powershell
$artermProof = 'kept-on-host'
$artermPid = $PID
$artermCwd = (Get-Location).Path
$PID; $artermProof; (Get-Location).Path
```

Нажмите Ctrl+], чтобы отсоединить клиент. Если сочетание перехватывается, закройте только локальную вкладку клиента. Хост должен работать с вошедшим пользователем. Повторите ту же команду локально:

```powershell
arterm connect my-devbox MyProof --shell powershell
```

В повторно подключённом удалённом PowerShell:

```powershell
$PID; $artermProof; (Get-Location).Path
($PID -eq $artermPid) -and ($artermProof -eq 'kept-on-host') -and ((Get-Location).Path -eq $artermCwd)
```

Ожидаются прежний PID, kept-on-host, прежний каталог и True. В дальнейшем возвращайтесь той же командой. Для завершения проверки введите exit в удалённой оболочке: процесс завершится, его состояние уже не восстановить.

## Восстановление и отмена

При сбое используйте arterm doctor my-devbox, проверьте аккаунты и сеть; при необходимости восстановите вход клиента через arterm --login. Не удаляйте записи восстановления и не переустанавливайте работающий хост. Обновление по умолчанию не прерывает активные сеансы. На хосте arterm-host stop --disable сохраняет остановку; arterm-host start запускает его снова, но не возвращает потерянные оболочки. Удаление программы сохраняет данные. Отзыв доверия сертификату описан в руководстве.

<a id="ограничения"></a>
<a id="расширенное-локальное-управление"></a>

Управляемые send/read требуют новой поддерживаемой сессии PowerShell/pwsh и совпадающей доверенной локальной идентичности подключения. Старые оболочки не дооснащаются. В ветке разработки проверка прямого ввода и независимая проверка архивов передачи ещё не завершены; публикация не подтверждает все возможности ветки, неизвестные версии остаются непроверенными. Произвольные TUI, смешанные архитектуры и Windows Sandbox не сертифицированы. Автоматическое снятие блокировки файлов не гарантирует безопасность. Подробности — в английском руководстве.
